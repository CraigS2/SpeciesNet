Partner Species API Documentation

The partner species API lets an approved partner service pull this site's species list server-to-server, so the partner can link its own listings to the matching species pages here. It is read-only and authenticated with a per-partner API key rather than a user account.

Authentication

Partner keys are issued by a site administrator on request — there is no self-service page. The raw key is handed over exactly once, over a secure channel; only a hash of it is stored here, so a lost key can't be recovered, only replaced. Keep it on your server and never embed it in a browser page or mobile app.

Send it on every request as a header (never in the URL or query string):

X-Partner-Api-Key: <your-partner-api-key>

Key rotation: a partner can have a second key active alongside the current one, so you can switch to a new key without downtime. Ask the administrator for the new key, deploy it, then let them know so the old key can be retired. Both keys share the same rate limit.

Rate limiting

Requests are limited per partner, by default to 120 requests per hour. Going over returns 429; wait the number of seconds in the response (also sent as a Retry-After header) before trying again. With page sizes up to 1,000 a full sync takes only a handful of requests, so the limit is rarely a concern for a normal daily or hourly sync.

Pagination

Every list response is wrapped in count, next, previous and results. Follow next until it is null to read every page.

  • ?page_size= — results per page, default 500, maximum 1,000.
  • ?page= — page number, starting at 1.
Incremental sync: the since parameter

?since= returns only species updated at or after that time. Accepts a date (2026-10-01) or an ISO 8601 datetime (2026-10-01T00:00:00Z). Prefer the Z suffix for UTC; if you send an offset like +00:00, URL-encode the + as %2B. An unparseable value is a client error (400), not silently ignored, so a typo can't turn an incremental sync into a full one. Store the time you started each sync and pass it as since on the next run.

Endpoints
  • Species
  • CARES Species
GET /api/partner/species/

Every species on the site, ordered by name.

Query parameters: since, page, page_size (all optional).

Example request

curl "https://yourdomain.example.com/api/partner/species/?since=2026-10-01" \
  -H "X-Partner-Api-Key: YOUR_KEY"

Example response

{
  "count": 1,
  "next": null,
  "previous": null,
  "results": [
    {
      "id": 1234,
      "name": "Xenotoca doadrioi",
      "alt_name": "",
      "url": "https://yourdomain.example.com/species/1234/",
      "last_updated": "2026-10-31T14:02:11Z"
    }
  ]
}

Fields

GET /api/partner/cares-species/

Only species flagged as CARES (conservation priority) species, with their CARES classification. Same fields as Species, plus the two below.

Query parameters: since, page, page_size (all optional).

Example request

curl https://yourdomain.example.com/api/partner/cares-species/ \
  -H "X-Partner-Api-Key: YOUR_KEY"

Example response

{
  "count": 1,
  "next": null,
  "previous": null,
  "results": [
    {
      "id": 1234,
      "name": "Xenotoca doadrioi",
      "alt_name": "",
      "url": "https://yourdomain.example.com/species/1234/",
      "last_updated": "2026-10-31T14:02:11Z",
      "cares_classification": "CCR",
      "cares_classification_display": "Critically Endangered"
    }
  ]
}
